# SIMD-optimized primitives 🟧

**What it is.** Four everyday primitives — `strlen`, `memchr`, `memcpy`, and a
UTF-8 validator — each implemented **four ways** so you can read the same idea
climb from a naive byte loop to hand-tuned vector code:

1. a **scalar reference** (`scalar.c`) — correct by inspection, the yardstick;
2. **SSE2/AVX2 intrinsics** (`simd_intrin.c`) via `<immintrin.h>`;
3. **hand-written assembly** (`simd_asm.S`, SysV AMD64) — the *star artifact*,
   commented essentially per-instruction;
4. a **runtime-dispatched `*_best`** pointer (`dispatch.c`) that picks the
   fastest variant this CPU can run, the way glibc's IFUNC resolvers do.

`bench.c` differential-tests every variant against the scalar reference **and**
against glibc, then measures the throughput gap and lets the code explain it.

> **On your own box only.** Nothing here is offensive, but it is a low-level
> lab: you compile it, you run it, on hardware you own. The one security-shaped
> component — the UTF-8 validator — is written as a *defensive* control (see
> **Defense**), because malformed UTF-8 is a real filter-bypass vector.

## What you'll learn

- The **core SIMD search idiom**: `pcmpeqb`/`vpcmpeqb` (compare 16/32 bytes at
  once, match → `0xFF`) + `pmovmskb`/`vpmovmskb` (pack each byte's high bit into
  an integer) + `tzcnt`/`bsf` (index of the first match). One compare finds a
  byte among 16 or 32.
- **Aligned vs unaligned loads**, and the **page-safety** rule that makes a
  no-length `strlen` safe: a vector load aligned to its width can't cross a
  4096-byte page, so it never faults into unmapped memory.
- **`rep movsb` and ERMS** — why three instructions beat a hand-rolled copy
  loop on modern Intel, and when they don't.
- **`cpuid` + `xgetbv`** feature detection done correctly, including the
  OS-XSAVE (`xgetbv`) check that gates legal AVX use.
- **Runtime dispatch** (function multiversioning / the IFUNC pattern) and
  `__attribute__((target(...)))`.
- **Why the compiler won't auto-vectorize `strlen`** — and will vectorize the
  same work when the trip count is known (`asm/demo.c`).

## Build & run (Linux / WSL x86-64)

```bash
make test     # build, then differential-check every variant vs scalar + glibc
make bench    # same, then print GB/s next to glibc for each primitive
make asm      # regenerate asm/demo.{O0.s,s,O2.s} (works on any host)
make disasm   # disassemble simd_asm.o to prove the committed encodings
```

The runnable binary links `simd_asm.S` (System V ABI) and is **Linux-only**.
The intrinsics and scalar code are portable C; the committed assembly is
generated by a cross-targeting clang and is host-portable to *read*.

## How it works

| file | role |
|------|------|
| `simd_primitives.h` | the shared contract: prototypes for all four variants + the dispatch pointers. |
| `cpuid.c` | `simd_detect_features()` — `cpuid` leaves 1 and 7 **plus** the `xgetbv` OS-YMM check that legalizes AVX. |
| `scalar.c` | the reference `strlen`/`memchr`/`memcpy` and the **fully-checked** UTF-8 decoder (`utf8_decode_one`, Unicode Table 3-7). |
| `simd_intrin.c` | SSE2 + AVX2 versions; each function opts into its ISA with `target(...)` so the binary still runs on old CPUs. |
| `simd_asm.S` | **hand-written** `strlen_avx2`, `memchr_sse2`, `memcpy_erms`, `memcpy_sse`. Read this. |
| `dispatch.c` | `simd_init()` resolves `strlen_best`/`memchr_best`/… from the detected features. |
| `bench.c` | correctness gate + throughput harness. |
| `asm/demo.c` | the scalar `strlen` (+ a bounded twin) isolated for scalar-vs-vector **codegen diffing**. |

### The strlen page-safety trick (the subtle part)

`strlen` gets no length, so a 32-byte load must not read past the terminator
into an unmapped page. Both the intrinsics and `simd_asm.S` handle it the same
way: **align the pointer down** to the vector width, do one aligned load, and
**shift the zero-mask right** by the misalignment to ignore bytes before the
string start. Because the load is width-aligned and 4096 is a multiple of 32,
it can only touch the page the string already occupies. After that first block,
every load is naturally aligned. (Watch out for one CPU gotcha the asm calls
out: `shr` by a count of 0 leaves flags unchanged, so we branch on an explicit
`test`, not on `shr`'s flags.)

## Benchmark: the gap, explained

Run `make bench`. You will see roughly this shape (numbers vary by CPU/RAM; the
*ordering* and the *why* are the lesson):

- **`memcpy`: glibc ≈ `memcpy_erms_asm` ≫ `memcpy_sse_asm` ≫ scalar.**
  On a CPU with **ERMS** (Enhanced REP MOVSB, `CPUID.07H:EBX[9]`), `rep movsb`
  is *microcoded* into wide, cache-line-granular transfers that saturate memory
  bandwidth — so for large copies the whole memcpy is literally three
  instructions and glibc jumps straight to it. The explicit 16-byte SSE loop
  moves the same bytes but pays per-iteration loop overhead and can't beat the
  memory controller, so at large sizes it converges toward — but rarely exceeds
  — the ERMS path. (For *tiny* copies the calculus flips: `rep movsb` has a
  fixed startup cost, which is why real memcpys branch to overlapping vector
  stores for small `n`. Our teaching version keeps the two paths separate.)

- **`strlen`/`memchr`: vector ≫ scalar, by ~8–16×.**
  The scalar loop retires ~1 byte/iteration and is branch-mispredict-bound at
  the terminator. The vector version tests 16–32 bytes per `pcmpeqb`+`pmovmskb`
  and branches once per block, so it processes memory at close to load
  bandwidth. glibc's is a hair faster still (aligned-head handling, 4×-unrolled
  inner loop, `vzeroupper` discipline) — read its source to see the extra
  polish, but the algorithm is exactly the one here.

- **`utf8_validate`: SIMD ≫ scalar on ASCII-heavy input.**
  The fast path skips 16 all-ASCII bytes with a single `pmovmskb == 0` test;
  only genuinely non-ASCII stretches drop to the scalar decoder.

## Defense

Two defensive lessons live here, and they are the more instructive half:

1. **Canonical UTF-8 validation is a security control.** The validator rejects
   **overlong** encodings (`C0 80` for NUL), **surrogates** (`ED A0 80`), and
   **out-of-range** code points (`> U+10FFFF`). These are not pedantry: a filter
   that blocks `"../"` but decodes non-canonical UTF-8 *afterward* can be walked
   right past with an overlong `2F`; smuggled surrogates corrupt downstream
   UTF-16 consumers. Validate at the trust boundary, reject non-canonical bytes,
   *then* interpret. The SIMD fast path exists so you can afford to validate
   **everything** at line rate instead of skipping it "for performance".

2. **These primitives are what overflows abuse — so build them hardened.**
   A one-byte `strlen`/`memcpy` mismatch is a classic corruption bug. Unlike the
   deliberately-vulnerable targets elsewhere in this section, this project is
   built with **every mitigation on** (`-fstack-protector-strong`,
   `_FORTIFY_SOURCE=2`, `-fPIE -pie`, full RELRO) and the assembly declares a
   **non-executable stack** (`.note.GNU-stack`) — the `W^X` default that costs an
   attacker their easiest shellcode landing pad. The Makefile comments spell out
   each flag and what it buys.

## Assembly notes

- **`simd_asm.S`** is the artifact to study. It documents the SysV ABI contract,
  the register discipline (every routine is a red-zone leaf that touches only
  caller-saved regs — no prologue), the page-safe aligned-load strlen, the
  SSE2-only byte-broadcast for memchr (`movd`→`punpcklbw`→`punpcklwd`→`pshufd`),
  the ERMS `rep movsb`, and the closing `vzeroupper` that avoids the AVX↔SSE
  transition stall. `make disasm` prints the genuine encoded bytes.
- **`asm/demo.annotated.s`** is the hand-annotated `-O1` output for the scalar
  `strlen`. Its companions show the **auto-vectorization lesson** directly:
  - `asm/demo.s` (`-O1`) and `asm/demo.O2.s` (`-O2`): `scalar_strlen` stays a
    scalar byte loop **even at -O2** — the compiler may not speculate a wide
    load past an unknown-length buffer. Its twin `count_nonzero_bounded`, with a
    *known* count, **does** auto-vectorize at `-O2` (`pcmpeqb` + a `paddq`
    reduce). That contrast is exactly *why* fast `strlen`/`memchr` are
    hand-written: the optimizer refuses the over-read the aligned-load trick
    makes safe.
  - `asm/demo.O0.s`: the naive statement-by-statement mapping.

## Going further

- **Stretch: a full-vector UTF-8 validator.** This project's SIMD validator is
  an honest *ASCII fast path* with a scalar fallback for multibyte runs — not a
  branch-free vector validator. The state of the art (Lemire & Keiser,
  "Validating UTF-8 In Less Than One Instruction Per Byte") checks continuation
  structure and ranges entirely in vectors using shuffle-based lookup tables.
  Porting that into `simd_intrin.c` (and then `.S`) is the natural next step.
- **AVX-512 `strlen`** with mask registers (`vpcmpeqb` → `k`-reg, `kmovq`,
  `tzcnt`) processes 64 bytes/compare — but mind the frequency-throttling
  tradeoff on some parts.
- **Precise ERMS/FSRM dispatch**: test `CPUID.07H:EBX.ERMS[9]` and the newer
  `Fast Short REP MOV` and branch small vs large copies the way glibc does in
  `sysdeps/x86_64/multiarch/`.
