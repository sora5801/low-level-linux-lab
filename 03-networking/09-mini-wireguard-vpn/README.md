# A VPN (mini-WireGuard) 🟥

**What it is.** A point-to-point encrypted tunnel built the way WireGuard is: a
**TUN** device carries IP packets to userspace, we wrap each one in **ChaCha20-
Poly1305** and ship it over **UDP**, and the session keys come from a **Noise_IK**
handshake using **Curve25519 (X25519)** for the Diffie-Hellman and **BLAKE2s**
for hashing/HKDF. It has a **nonce counter** and a **sliding-window anti-replay**
guard on the receive side, and it sets the interface **MTU** so encrypted packets
never fragment. The cryptographic primitives are implemented here (as annotated
transcriptions of vetted reference code) so the whole construction is readable in
one repo, not hidden behind a library.

This is 🟥 (a giant) shipped as an honest **teaching core**: the handshake, the
AEAD data path, replay protection, and the TUN/UDP plumbing are complete and
interoperate between two instances of this program. What it deliberately leaves
out (rekey timers, cookies/DoS mitigation, roaming edge-cases, many peers,
constant-time hardening) is listed in **Going further**.

## What you'll learn

- **The TUN device**: `open("/dev/net/tun")` + `ioctl(TUNSETIFF)` to get a
  file descriptor that *is* a network interface; `read()` returns outbound IP
  packets, `write()` injects inbound ones. Plus the netdevice ioctls
  `SIOCSIFMTU` / `SIOCSIFFLAGS` to size and raise the link.
- **The Noise Protocol Framework**, concretely the **IK** pattern: how a
  SymmetricState (`ck` chaining key + `h` transcript hash) absorbs four
  Diffie-Hellman results (`ee, es, se, ss`) to give mutual authentication *and*
  forward secrecy *and* initiator identity-hiding in two messages.
- **The primitives, from the inside**:
  - **X25519** (RFC 7748): the Montgomery ladder, field arithmetic mod
    2^255-19, constant-time conditional swaps.
  - **ChaCha20** (RFC 8439): an ARX stream cipher — the quarter round is pure
    32-bit add/rotate/xor (this is `asm/demo.c`).
  - **Poly1305**: a one-time authenticator over the field 2^130-5.
  - **BLAKE2s** (RFC 7693) and the **HMAC → HKDF** built on it.
- **AEAD discipline**: encrypt-then-MAC, associated data, and the cardinal rule
  that a `(key, nonce)` pair must never repeat.
- **Anti-replay**: why authentication alone does not stop replay, and the
  RFC 6479 sliding-window bitmap that stops it without O(window) work per packet.
- **MTU math**: why the tunnel MTU is 1420 and what each subtracted byte pays for.
- The syscalls: `socket`(41), `bind`(49), `sendto`(44), `recvfrom`(45),
  `poll`(7), `open`(2), `ioctl`(16), `read`(0)/`write`(1), `getrandom`(318).

## Build & run

**Platform: Linux only** (WSL2 works). It needs `/dev/net/tun` and
`CAP_NET_ADMIN` (run as root). It does **not** build or run on Windows/macOS —
the TUN ioctls and headers are Linux kernel interfaces. The teaching assembly,
however, is generated by a cross-targeting clang and builds on any host.

```bash
make                 # builds ./mini-wg  (clang -Wall -Wextra)

# 1) make two keypairs (no privileges needed):
./mini-wg -g         # prints:  private = <44 b64>   public  = <44 b64>
./mini-wg -g         # run again for the second peer

# 2) bring up two tunnels on one machine (two shells, both as root):
#    Peer A is the RESPONDER (no -e); Peer B is the INITIATOR (-e A's endpoint).
sudo ./mini-wg -i wg0 -l 51820 -k <A_priv> -R <B_pub>
sudo ip addr add 10.9.0.1/24 dev wg0

sudo ./mini-wg -i wg1 -l 51821 -k <B_priv> -R <A_pub> -e 127.0.0.1:51820
sudo ip addr add 10.9.0.2/24 dev wg1

# 3) traffic to 10.9.0.1 now flows encrypted over UDP:
ping 10.9.0.2        # from A's side (or 10.9.0.1 from B's)
```

Watch the handshake logs on stderr ("sent handshake initiation", "session
established"). For a cleaner two-peer test, put each side in its own network
namespace (`ip netns`) so the kernel routes 10.9.0.0/24 across the tunnels rather
than short-circuiting on loopback.

```bash
make asm             # regenerate asm/demo.{O0.s,s,O2.s} (any host)
make keygen          # print one fresh keypair
make run             # print the quickstart above
```

Options: `-g` (keygen), `-k PRIV` / `-R PEERPUB` (base64 keys), `-l PORT` (local
UDP port, default 51820), `-e IP:PORT` (peer endpoint ⇒ this side initiates),
`-i NAME` (TUN name, default `wg0`).

## How it works

Eight small translation units, bottom-up:

- **`wg.h`** — shared fixed-width types, all crypto sizes, the **wire-format byte
  offsets** (init / response / data messages, drawn out field by field), the
  **MTU arithmetic**, and inline endianness/rotate/`secure_zero` helpers.
- **`chacha20poly1305.c`** — the AEAD (RFC 8439): `chacha20_block` (the ARX
  keystream), the Poly1305 one-time authenticator (poly1305-donna math, 5×26-bit
  limbs mod 2^130-5), and `aead_seal`/`aead_open` that combine them with a
  constant-time tag compare.
- **`blake2s.c`** — BLAKE2s (RFC 7693), then `hmac_blake2s` and `hkdf` — the KDF
  the handshake ratchets keys with.
- **`x25519.c`** — Curve25519 scalar multiplication, a commented transcription of
  TweetNaCl: the Montgomery ladder and the `gf` field arithmetic.
- **`replay.c`** — the RFC 6479 sliding-window anti-replay bitmap: a power-of-two
  ring of bits advanced by zeroing only the words about to be reused.
- **`noise.c`** — the **Noise_IK state machine**: `mix_hash` / `mix_key` /
  `encrypt_and_hash` / `decrypt_and_hash`, then the two message builders/consumers
  and `noise_begin_session` (Split). Transport `encrypt`/`decrypt` live here too,
  each packet an AEAD box keyed by the per-packet counter.
- **`tun.c`** — `tun_open` (clone `/dev/net/tun`, `TUNSETIFF` with
  `IFF_TUN|IFF_NO_PI`) and `tun_configure` (MTU + link-up via a control socket).
- **`util.c`** — `getrandom(2)` wrapper and base64 (the key encoding).
- **`vpn.c`** — the driver: parse args, load keys, bring up TUN + UDP, then a
  single `poll()` loop multiplexing the two fds. TUN-readable → encrypt → UDP;
  UDP-readable → dispatch by message type (init/response/data); timeout →
  re-dial if we are the initiator and still have no session.

**Data flow.**

```
 app ─► kernel routes to wg0 ─► [TUN read] ─► noise_transport_encrypt ─► UDP ─┐
                                                                              │
 app ◄─ kernel routes from wg0 ◄─ [TUN write] ◄─ noise_transport_decrypt ◄─ UDP┘
                                                    │
                                                    └─ replay_check (drop dups)
```

**The handshake (two messages, IK).**

```
initiator                                             responder
  |  msg1: type, index, e_pub, ENC(s_pub), ENC(timestamp)   |
  |-------------------------------------------------------->|  authenticate,
  |                                                         |  learn peer, reply
  |  msg2: type, indexes, e_pub, ENC(empty)                 |
  |<--------------------------------------------------------|
  |  Split(ck) → two directional transport keys on both sides|
```

Message 1 mixes `e`, then `es = DH(e_i, s_r)`, sends the initiator's static key
*encrypted* (identity hiding), then `ss = DH(s_i, s_r)`, then an encrypted
timestamp that both authenticates the initiator and lets the responder reject
replayed initiations. Message 2 adds `ee` and `se`, completing forward secrecy.
Every DH result is folded into `ck`; both sides derive identical keys only if
every byte of the transcript agreed.

## Assembly notes

Every real translation unit pulls in project or system headers, so per
CONVENTIONS the didactic assembly is an **extraction**: [`asm/demo.c`](asm/demo.c)
is the **ChaCha20 quarter round + block**, self-contained with its own types and
no headers, so `clang -S` yields clean, teachable output.

[`asm/demo.annotated.s`](asm/demo.annotated.s) annotates the `-O1` output. The
lessons visible there:

- **ChaCha is ARX and *only* ARX.** The generated code is nothing but `addl`,
  `xorl`, and `roll` on registers — no table loads, no data-dependent branches.
  That is the machine-level *proof* that ChaCha is constant-time, the property
  the whole AEAD leans on.
- **The rotate idiom compiles to one instruction.** `(v<<c)|(v>>(32-c))` in
  `rotl32` becomes a single `roll $c` — watch the optimizer recognise it.
- **Register pressure with 16 state words and 15 GP registers.** `chacha20_block`
  keeps a working set in registers and rotates a few words (x0, x8, x9, x10, x11)
  through named stack spills as the *diagonal* quarter rounds reach across the
  matrix. The annotation names which register holds which `x[i]` at each step.
- **The feed-forward add** `s[i] + x[i]` at the end is what makes the 20-round
  permutation one-way.

Compare the three levels: [`demo.O0.s`](asm/demo.O0.s) (naive, everything spilled
— the quarter round is a real `call`), [`demo.s`](asm/demo.s) (`-O1`, the
annotated baseline), and [`demo.O2.s`](asm/demo.O2.s) (`-O2`, the loop
vectorised into SSE lanes). Regenerate with `make asm`.

## Going further (the `Stretch:` from the list)

Turn the teaching core into something closer to real WireGuard:

- **Rekeying & timers.** WireGuard rekeys every ~2 minutes / 2^60 messages and
  keeps current+previous+next sessions so packets never drop across a rekey. We
  keep one session and no timer — add the `REKEY_AFTER_*` state machine.
- **Cookies / DoS resistance.** Real WireGuard appends `mac1`/`mac2` (keyed
  BLAKE2s) to every handshake message and issues encrypted **cookie replies**
  under load so an attacker cannot cheaply force expensive DH work. We omit
  message type 3 and the macs — state so in the code.
- **Many peers & routing (`AllowedIPs`).** A real device is a hash of peers keyed
  by public key, with a longest-prefix trie mapping inner destination IPs to the
  peer to encrypt for. We hard-wire exactly one peer.
- **Constant-time everywhere / secret-independent memory.** The transcriptions
  here (TweetNaCl, poly-donna) are constant-time, but the glue is not audited;
  production code also uses `mlock`, guards against timing in every compare, and
  wipes stacks. Treat this as a learning artifact, **not** a secure VPN.
- **IPv6, GSO, and multi-threading.** Outer IPv6, segmentation offload for
  throughput, and a worker-per-CPU model with per-peer queues.

Production reading: WireGuard's whitepaper and `wireguard-go`
(`device/noise-protocol.go`) or the kernel module (`drivers/net/wireguard/`).
