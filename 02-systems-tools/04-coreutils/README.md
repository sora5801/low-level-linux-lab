# coreutils, but really 🟩

**What it is.** A busybox-style multiplexer that reimplements six classic Unix
tools — **cat, cp, ls, wc, xargs, and tailf** (`tail -f`) — with an obsessive
focus on the correctness details that naive clones get wrong: short reads and
writes, `EINTR`, sparse-file holes, the raw `getdents64` record stream, `ARG_MAX`
budgeting, and inotify-based file following through truncation and log rotation.
One small binary contains all six; it decides which tool to be from `argv[0]`
(via symlinks) or its first argument. Difficulty: 🟩 (green) — the concepts are
approachable, but "really" means the error paths are the point.

**Platform: Linux (or WSL) only.** It uses `getdents64`, `inotify`,
`copy_file_range`, and `SEEK_HOLE`/`SEEK_DATA`, none of which exist off Linux.
The teaching assembly (`asm/`) is generated by a cross-targeting clang and is
host-portable.

## What you'll learn

- **The read/write contract nobody reads.** `write(2)` and `read(2)` may move
  *fewer* bytes than asked, and may fail with `EINTR` when a signal interrupts a
  blocked call. `write_all()` / `read_retry()` / `copy_fd()` in `util.c` encode
  the correct loops once; every tool uses them.
- **Sparse files.** `SEEK_DATA`/`SEEK_HOLE` let you walk a file as alternating
  holes and data; `copy_file_range(2)` copies in-kernel (and can reflink). `cp`
  preserves holes instead of inflating a sparse image to its full logical size.
- **Directory internals.** `getdents64(2)` hands you a packed buffer of
  variable-length `struct linux_dirent64` records; you stride by `d_reclen`.
  `fstatat(…, AT_SYMLINK_NOFOLLOW)` stats relative to an open dir fd.
- **The `wc` state machine.** Counting words across buffer boundaries (carry the
  in-word bit) and counting UTF-8 *characters* vs *bytes* (skip `10xxxxxx`
  continuation bytes). This is the routine extracted into `asm/demo.c`.
- **`ARG_MAX`.** `execve` rejects an over-long argv+envp with `E2BIG`. Correct
  `xargs` budgets against `sysconf(_SC_ARG_MAX)` *minus the environment's size*
  *minus headroom*, counting each argument's bytes **and** its pointer slot.
- **inotify.** Following a file means handling three cases: append (`IN_MODIFY`),
  truncation (size shrinks below your offset), and rotation (`IN_MOVE_SELF` /
  `IN_DELETE_SELF` → reopen the *path*, not the old inode).

## Build & run (Linux / WSL)

```bash
make            # builds ./coreutils with clang -Wall -Wextra -O2
make links      # creates cat cp ls wc xargs tailf symlinks to ./coreutils
make test       # runs a small smoke test over the source tree

# Two invocation styles (busybox model):
./coreutils wc -l README.md          # subcommand form
./cat coreutils.h | ./wc -lwc        # applet-name form (after `make links`)
./ls -l .
./cp util.c /tmp/util.copy           # try it on a sparse file to see holes kept
./tailf -n 20 /var/log/syslog        # follow; append/rotate it in another shell
printf 'a\nb\nc\n' | ./xargs echo    # batches items under ARG_MAX, then execs
```

Prove the sparse copy actually preserves holes:

```bash
truncate -s 1G big.img               # a 1 GiB file that is ALL hole (0 blocks)
dd if=/dev/urandom of=big.img bs=4k count=1 seek=100 conv=notrunc  # one data block
./cp big.img copy.img
du -h --apparent-size big.img copy.img   # both report ~1G logical size...
du -h               big.img copy.img   # ...but both use only a few KiB on disk
```

## How it works (file by file)

- **`coreutils.h`** — shared declarations: the robust-I/O prototypes and each
  applet's `int <tool>_main(int, char**)`.
- **`util.c`** — the heart of "really": `write_all` (loop past short writes,
  retry `EINTR`), `read_retry` (retry `EINTR`, surface EOF), `copy_fd` (the
  streaming copy), and the `warn`/`die` diagnostics that prefix every message
  with the applet name.
- **`coreutils.c`** — the multiplexer. A `name → function` table; `main` does
  `argv[0]` basename lookup (symlink form) or shifts `argv` by one (subcommand
  form). Adding a tool is one table row.
- **`cat.c`** — sizes its buffer from the source's `st_blksize`, streams with
  `copy_fd`, treats `-` as stdin, and keeps going (with non-zero exit) if one
  file fails.
- **`cp.c`** — the strategy ladder: (1) `SEEK_DATA`/`SEEK_HOLE` + in-kernel
  `copy_file_range` per data segment, leaving holes as holes; (2) fall back to a
  manual read/write loop that detects all-zero blocks and `lseek`s the
  destination forward to re-punch them. Preserves permission bits with `fchmod`,
  and checks `close(2)` so a deferred write error (`ENOSPC`) can't be lost.
- **`ls.c`** — opens the directory `O_DIRECTORY`, loops `getdents64` walking
  records by `d_reclen`, sorts, and renders either the long format (mode string,
  link count, user/group names, size, date) or a terminal-width multi-column
  layout (down-then-across, sized via `ioctl(TIOCGWINSZ)`).
- **`wc.c`** — the counting DFA `wc_count`, run over 64 KiB chunks with the
  in-word bit carried in `struct wc_state`. Selects `-l/-w/-c/-m` columns and
  prints a `total` line for multiple files.
- **`xargs.c`** — slurps stdin, splits on whitespace (or NUL with `-0`), and
  packs items into batches under the computed `ARG_MAX` budget (and any `-n`
  cap), then `fork`+`execvp`s each batch and reaps it, tracking the worst exit
  status.
- **`tailf.c`** — prints the last *N* lines (read backward in blocks), then
  follows via inotify: `IN_MODIFY` drains new data, a size shrink is detected as
  truncation, and `IN_MOVE_SELF`/`IN_DELETE_SELF`/`IN_IGNORED` trigger a reopen
  of the path for log rotation.

## Assembly notes

The real applets include Linux-only headers, so they can't be cross-compiled to
assembly on a non-Linux host. Per the lab convention, `asm/demo.c` is a
**self-contained extraction** of the project's most instructive pure-logic
routine — `wc`'s counting state machine `wc_count` — with no `#include`s and its
own typedefs. It is the same algorithm as `wc.c`, so the committed assembly is
genuinely this project's code.

- [`asm/demo.annotated.s`](asm/demo.annotated.s) — the hand-annotated `-O1`
  output. It shows the whole state machine running in **registers**, touching
  memory only to load `in_word` on entry and write the five totals on exit. Two
  highlights worth the price of admission:
  - The UTF-8 test `(c & 0xC0) != 0x80` compiles to a single **signed** compare
    (`cmpb $-64; setge`) — the optimizer recognised a bit-mask test as a range
    test.
  - The `words++` on a whitespace→word transition is **branchless**
    (`sete`/`andb`/`addq`), so random whitespace never mispredicts.
- [`asm/demo.O0.s`](asm/demo.O0.s) — the naive mapping: every `if` a branch,
  every variable spilled to the stack. Easiest to read statement-by-statement.
- [`asm/demo.s`](asm/demo.s) — the `-O1` baseline that the annotation explains.
- [`asm/demo.O2.s`](asm/demo.O2.s) — `-O2` goes further: it drops the frame
  pointer, reuses `%rbp` as a data register, and sinks the register-saving
  prologue *inside* the `n > 0` branch so the empty-chunk path never spills.

Regenerate the three machine-generated files with `make asm` (works on any host;
clang cross-targets `x86_64-pc-linux-gnu`). The exact commands are in the
Makefile's `asm` target and mirror `CONVENTIONS.md`.

## Going further (the `Stretch:` goals)

- **cat**: add `posix_fadvise(POSIX_FADV_SEQUENTIAL)` and, for regular-file to
  regular-file, `copy_file_range`/`sendfile` to skip the userspace bounce.
- **cp**: preserve ownership (`fchown`), timestamps (`futimens`), xattrs, and
  ACLs; add `-r` for trees (`openat` recursion) and `--reflink=auto`.
- **ls**: color output, `-h` human sizes, `-t`/`-S`/`-r` sort keys, and a proper
  multi-byte-aware column width (display width, not byte length).
- **wc**: true locale-aware `-m` via `mbrtowc`, and the `-L` longest-line column.
- **xargs**: `-P` parallelism (multiple children in flight), `-I{}` replacement,
  and `-r/--no-run-if-empty` semantics.
- **tailf**: follow multiple files at once (one watch each), `--retry` back-off,
  and `-F` (`--follow=name --retry`) exactly matching GNU tail.

What production does: GNU coreutils' `copy.c` is ~2000 lines handling every one
of the above; `tail.c` juggles inotify **and** a `fstat` polling fallback for
filesystems inotify can't watch (NFS). This project is the honest teaching core
of those ideas, not a drop-in replacement.
